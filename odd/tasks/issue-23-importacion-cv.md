## Specs
S1. «Trabajá desde el `origin/master` actual.» «No borres otros worktrees ni ramas.» «No lo modifiques ni lo uses como base.» «No hagas merge ni cierres la issue.»
S2. «Seleccionar documento → extraer texto → mostrarlo en un editor → corregirlo → confirmar análisis con IA → revisar los datos propuestos → aplicar cambios al perfil.» «La IA no debe ejecutarse automáticamente al seleccionar un archivo.» «El usuario también debe poder reemplazar el texto extraído pegando contenido manualmente.»
S3. «Priorizá PDF con texto seleccionable porque es habitual para enviar CV.» «Implementá bien un formato adicional antes que incorporar dos lectores incompletos.» «Markdown `.md` debe seguir funcionando.» «Conservá ese contrato para analizar texto» `POST /api/preferencias/importar-cv/analizar`.
S4. «El endpoint debe estar autenticado mediante la protección actual de Firebase.» «Extensión permitida.» «Tipo de archivo y contenido real cuando sea posible.» «Tamaño máximo.» «Documento vacío o corrupto.» «Texto extraído vacío.» «Caracteres o codificación inválidos.» «No trunques silenciosamente el contenido.» «No almacenes los bytes originales en PostgreSQL ni en el filesystem permanentemente.» «No envíes binarios de PDF/DOCX a DeepSeek.» «No registres el contenido privado del CV en logs.»
S5. «Usá límites explícitos, por ejemplo hasta 5 MiB para el documento binario y el límite de texto vigente para el CV base, ajustándolos únicamente cuando exista justificación.» «Si el texto completo excede el límite admitido, devolvé un error explicando el problema.» «Para PDF sin texto extraíble, mostrale al usuario que no se pudo recuperar texto y ofrecé pegarlo manualmente.»
S6. «El texto recién extraído debe ser un **borrador temporal**.» «No reemplaces automáticamente el CV base guardado ni las preferencias actuales.» «Si existe una edición del CV base sin guardar, no la sobrescribas por cargar otro archivo.» «La acción actual «Usar este archivo como mi CV base» debe funcionar con el texto ya extraído y corregido, pero seguir requiriendo guardado explícito.» «Si se selecciona otro archivo durante la revisión, preservá las decisiones pendientes o solicitá confirmación antes de descartarlas.» «Una respuesta HTTP tardía no debe reemplazar el borrador de un archivo más reciente.»
S7. «No perder secciones completas del CV.» «No truncar silenciosamente la entrada.» «No convertir una respuesta incompleta en una importación exitosa.» «No inventar habilidades o experiencia.» «No sustituir datos confirmados por información dudosa.» «No aplicar cambios al perfil automáticamente.» «Mostrar propuestas y preguntas.» «Conservar los cambios que el usuario decida mantener o rechazar.» «No cambies las reglas de matching ni los modelos de DeepSeek.»
S8. «Archivo no admitido.» «Documento demasiado grande.» «Documento dañado.» «Documento sin texto extraíble.» «Extracción incompleta o inválida.» «Error de red.» «Error del análisis con DeepSeek.» «Texto extraído → Texto revisado → Análisis completado → Perfil revisado → Cambios aplicados.» «Los errores deben permitir corregir o pegar texto sin empezar todo desde cero.» «Mantené accesibilidad básica, uso por teclado y diseño mobile.»
S9. Backend: «1. Markdown válido sigue admitido. 2. Un documento válido del nuevo formato devuelve texto útil. 3. Se conservan nombre, experiencia, educación e idiomas del documento sintético. 4. Un documento sin texto recuperable devuelve un error entendible. 8. El límite de tamaño se respeta. 9. El texto excesivo no se trunca silenciosamente. 10. Extraer texto no invoca DeepSeek. 11. El endpoint exige autenticación.»
S10. Frontend: «12. Se puede seleccionar el formato admitido. 13. El texto extraído aparece antes del análisis. 14. Se puede corregir el texto. 15. El análisis utiliza exactamente el texto revisado, no la extracción original. 16. Seleccionar un archivo no consume IA automáticamente. 17. Los errores muestran la opción de pegar texto. 18. Los borradores previos no se sobrescriben accidentalmente. 19. Un error de red no borra el texto revisado. 20. El flujo Markdown existente conserva su funcionamiento.»
S11. Integración: «21. Documento sintético → extracción → corrección → análisis IA simulado → revisión de perfil → aplicación explícita. 22.
