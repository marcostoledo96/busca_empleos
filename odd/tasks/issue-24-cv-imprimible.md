## Specs

S2. «Abrir generador de CV → cargar datos confirmados → elegir enfoque laboral → seleccionar contenido → revisar la vista previa → imprimir o guardar como PDF.» «Quiero **una sola plantilla**, no un diseñador de CV con múltiples temas.» «No necesito un servicio de generación de PDF en el backend.»

S4. «No uses automáticamente el archivo `cv.md` del repositorio como fuente de verdad.» «No inventes experiencia, cargos, estudios, tecnologías, fechas, resultados ni nivel de inglés.» «Los roles que el usuario quiere conseguir no deben confundirse con experiencia demostrada.» «Las tecnologías marcadas `ninguno` o `penalizable` no deben presentarse como habilidades dominadas.» «No incluyas políticas internas de matching, exclusiones, prompts, notas privadas ni instrucciones para la IA dentro del CV.» «Si faltan datos personales o profesionales, permití completarlos explícitamente y revisarlos.» «No inventes información para llenar una sección vacía.» «Si existen discrepancias entre el CV base y el perfil confirmado, mostrá una advertencia razonable y dejá que el usuario resuelva el contenido final. No decidas silenciosamente qué versión es correcta.»
S5. «Diseñá una plantilla de estilo profesional, sobrio y compatible con impresión A4.» «Nombre y datos de contacto.» «Perfil profesional.» «Experiencia laboral y proyectos relevantes.» «Educación.» «Habilidades y tecnologías.» «Idiomas.» «No es obligatorio mostrar secciones que no tienen información confirmada.» «La jerarquía visual debe ser clara y el documento debe poder leerse sin elementos decorativos innecesarios.»
S6. «El CV base puede contener Markdown extenso, varias secciones y texto que no corresponde incluir en un CV final.» «Implementá una manera sencilla de seleccionar contenido existente.» «Podés identificar secciones mediante encabezados Markdown y permitir que el usuario seleccione los bloques pertinentes, con opción de edición manual.» «No intentes convertir automáticamente cualquier Markdown arbitrario en experiencia estructurada perfecta.» «Si una sección no se puede identificar de forma confiable, conservá el texto original para selección o edición manual.» «No uses IA para inventar una versión resumida.»
S7. «Agregá un selector sencillo:» «Desarrollo de software.» «QA / Testing.» «Soporte IT.» «Salud / Administración sanitaria.» «Cambiar el enfoque debe permitir **priorizar, mostrar, ocultar u ordenar contenido existente**.» «El selector no debe crear experiencia que no existe.» «No cambies el cargo, la antigüedad o la formación simplemente porque seleccioné otro enfoque.» «Si no hay suficientes hechos confirmados para un enfoque, mostrámelo y permitime completar manualmente el documento.» «Cambiar el enfoque no debe modificar las preferencias de búsqueda ni guardar cambios en mi perfil.»
S8. «Implementá un borrador temporal con controles simples para:» «Corregir datos de contacto.» «Ajustar el resumen profesional.» «Seleccionar qué experiencias, proyectos y tecnologías mostrar.» «Reordenar las secciones principales cuando sea necesario.» «Editar texto manualmente.» «Ocultar secciones no relevantes.» «Las modificaciones del borrador imprimible no deben sobrescribir automáticamente el CV base ni las preferencias persistidas.» «No agregues una base de datos nueva para guardar versiones de CV.» «El usuario es responsable de confirmar las modificaciones manuales.» «La pantalla debe dejar claro que está preparando un documento para revisar, no certificando automáticamente todos sus datos.»
S9. «Al volver a generar el CV desde los datos guardados, una corrección hecha en la fuente debe reflejarse.» «Si el usuario ya está editando un borrador, no lo reemplaces silenciosamente cuando llegan nuevas respuestas HTTP.» «Ofrecé una acción explícita de recargar datos, con confirmación cuando existan cambios sin guardar.»
S10. «Incluí botones:» «**Volver a editar**» «**Imprimir / Guardar como PDF**». «Usá `window.print()` después de una acción explícita del usuario.» «Papel A4.» «Fondo blanco y texto legible.» «Márgenes adecuados.» «Evitar cortes en títulos, encabezados y bloques de experiencia.» «Permitir documentos de varias páginas.» «No superponer textos ni cortar contenido.» «Ocultar navegación, botones y elementos propios de la aplicación.» «Mantener enlaces de contacto y portfolio cuando sean relevantes.» «Funcionar independientemente del tema claro/oscuro de la aplicación.» «No fuerces el documento a una única página reduciendo la letra hasta volverlo ilegible.»
S11. «El generador debe funcionar con la autenticación existente.» «No envíes el CV a terceros ni a DeepSeek.» «No guardes documentos en servicios externos.» «No imprimas automáticamente al abrir la vista.» «No cambies estados de postulación.» «No ejecutes ninguna acción que marque una oferta como `cv_enviado`.» «No agregues migraciones de PostgreSQL si no son necesarias.» «No incorpores bibliotecas de PDF pesadas cuando la impresión nativa del navegador resuelve el objetivo.» «Renderizá el contenido del CV como texto seguro, sin insertar HTML arbitrario no sanitizado.»
